# A1.06 | Mini-défi Nuit du Code : créer un jeu en temps limité | 4e | Ch2,Ch3,Re1

:::rappel | Objectif de la séance
En binôme, je crée un petit jeu jouable à partir d'un univers imposé.

Le but n'est pas de faire un jeu parfait, mais de produire un jeu compréhensible, testable et présentable.
:::

## Mission

:::methode | Cahier des charges
Le jeu doit contenir :

1. un joueur contrôlé au clavier ;
2. au moins un décor ;
3. au moins un objet à attraper ;
4. au moins un obstacle ou une contrainte ;
5. un score ou des vies ;
6. une fin de partie claire.
:::

## Planifier avant de coder

:::methode | 10 minutes de préparation
Avant d'ouvrir trop de blocs, compléter :

- Titre du jeu : [[...]]
- Personnage contrôlé : [[...]]
- Objectif du joueur : [[...]]
- Bonus : [[...]]
- Danger : [[...]]
- Condition de victoire : [[...]]
- Condition de défaite : [[...]]
:::

:::rem | Rôles dans le binôme
Les deux élèves codent, mais les rôles changent toutes les 15 minutes :

- pilote : manipule Scratch ;
- copilote : lit la fiche, vérifie la règle, teste et repère les bugs.
:::

## Construire le jeu

:::methode | Étapes conseillées
1. Faire bouger le joueur.
2. Ajouter le score.
3. Ajouter un bonus.
4. Ajouter un obstacle.
5. Ajouter la victoire.
6. Ajouter la défaite.
7. Tester une partie complète.
8. Ajouter une seule amélioration si le jeu fonctionne déjà.
:::

## Présenter le jeu

:::methode | Présentation en 1 minute
1. Dire le titre du jeu.
2. Expliquer la règle.
3. Montrer comment on gagne.
4. Montrer un élément de code dont le binôme est fier.
5. Dire une amélioration possible.
:::

:::reussite | Critères de réussite
- Le jeu se lance avec le drapeau vert.
- On comprend ce qu'il faut faire.
- Le jeu peut se terminer.
- Le binôme a testé et corrigé au moins un bug.
- Le projet est présentable même s'il reste simple.
:::
